# Scheduled-learning replay-core test-intent map

This is the pre-commit redundancy pass required by `docs/TESTING.md`. Every retained test names one
primary observable risk, a distinct reachable mutant, and a nearest existing test that would not
catch it.

## Closed ordered event and adapter contracts (Task 1)

| Risk | Production branch or seam | Nearest existing test | Unique reachable mutant | Primary test |
| --- | --- | --- | --- | --- |
| Event inputs can skip a sequence, reverse time, or add a field | `learning_contract.parse_event` closed-envelope validator | `page-change/tests/test_canonical.py::test_rejects_content_after_root_object` only covers JSON framing | Change contiguous sequence check to accept `previous + 2`, or ignore an unknown envelope key | `test_learning_contract::test_event_log_rejects_gap_time_reversal_and_unknown_field` |
| An ordered log can accept a timestamp that precedes the prior event even when sequences stay contiguous | `learning_contract.canonical_event_log` nondecreasing-timestamp check | The gap/unknown-field assertions in the same test method exercise sequence contiguity and key closure, not timestamp ordering | Drop or invert the `occurred_at` comparison so a timestamp earlier than the prior event passes between two contiguous sequences | `test_learning_contract::test_event_log_rejects_gap_time_reversal_and_unknown_field` |
| A single out-of-place sequence can be silently accepted by parsing one event alone, even though a log starting there is invalid | `learning_contract.parse_event` vs `canonical_event_log` split (sequence-start rule lives only in the log validator) | The four `assertRaises` blocks in the same test method all wrap `parse_event(...)` calls inside `canonical_event_log(...)`, so under this mutant the exception `canonical_event_log` still raises would keep every `assertRaises` green — none of them can tell "rejected by `parse_event`" apart from "rejected by `canonical_event_log`" | Move the "log must start at 1" check into `parse_event` (or drop it from `canonical_event_log` without adding it elsewhere), so a lone `sequence: 2` event stops being accepted by `parse_event` in isolation | `test_learning_contract::test_event_log_rejects_gap_time_reversal_and_unknown_field`'s leading `self.assertEqual(parse_event(starts_at_two).sequence, 2)`, which sits outside every `assertRaises` block |
| The neutral adapter envelope can accept a malformed digest, an unknown field, or an outcome outside its closed enum, or can lose/rename a field on round-trip | `learning_contract._adapter_envelope_issues` / `parse_adapter_envelope` / `adapter_envelope_json` | No existing generic adapter-envelope test exists; the event-log test exercises `ReplayEvent` parsing, not the neutral `AdapterEnvelope` contract | Accept a `candidate_digest` that fails `SHA256_HEX`, permit an unknown envelope key, accept an outcome outside `pass\|regression\|critical\|inconclusive`, or drop/rename a field between `parse_adapter_envelope` and `adapter_envelope_json` | `test_learning_contract::test_adapter_envelope_rejects_invalid_digest_unknown_key_and_unknown_outcome` |

## Canonical decision and replay receipts (Task 2)

| Risk | Production branch or seam | Nearest existing test | Unique reachable mutant | Primary test |
| --- | --- | --- | --- | --- |
| A replayed decision digest can be silently dropped from `decision_receipt_sha256s` while the replay's other inputs stay unchanged | `replay_receipt` ordered decision-digest binding | `page-change/tests/test_scorer_conformance.py::test_three_complete_scorer_executions_are_byte_identical` covers scorer output stability, not replay receipts | Omit a decision digest from `decision_receipt_sha256s` (no reachable key-sorting mutant exists here: canonical key ordering is `canonical.dumps(..., sort_keys=True)`'s job, applied once globally, not a per-field step in either receipt builder) | `test_learning_contract::test_replay_receipt_is_byte_identical_for_identical_inputs` |
| `events_sha256` can fail to bind the full event payload, so a changed payload with unchanged sequence/timestamp goes undetected | `replay_receipt` event-log binding via `canonical_event_log` | `test_replay_receipt_is_byte_identical_for_identical_inputs` only replays the same event twice; it never varies the payload | Render `events_sha256` from sequence/timestamp/kind alone, dropping `payload` from `event_json` before hashing | `test_learning_contract::test_replay_receipt_events_sha256_changes_with_event_payload` |
| A decision receipt can accept `artifact_identities` that is not a canonical JSON object (a list, a scalar, a non-string key, or a value `canonical.dumps` cannot render), silently coercing it on serialization | `decision_receipt` / `_canonical_object_issues` | `test_replay_receipt_is_byte_identical_for_identical_inputs` only exercises the one valid `{"adapter": None}` shape | Drop the `_canonical_object_issues` call (or its non-string-key walk) so a list, a scalar, an int-keyed dict, or a non-JSON value (a `set`, a `NaN` float) passes through uncaught | `test_learning_contract::test_decision_receipt_rejects_malformed_artifact_identities` |
| A decision receipt can omit one provenance binding while remaining self-consistent, so two decisions with different evidence collide on `decision_id` | `decision_receipt` field binding into `decision_core` | No existing decision-receipt test | Omit the triggering-event digest, before-state digest, after-state digest, or `artifact_identities` from `decision_core` before hashing | `test_learning_contract::test_decision_receipt_id_changes_with_each_bound_input` |
| A decision receipt's own `decision_id` can be folded into the hash it derives from, making the ID self-referential and unverifiable by a third party | `decision_receipt` domain-separated hash computation | `test_decision_receipt_id_changes_with_each_bound_input` never recomputes the hash independently of the builder | Compute `decision_hash` over `decision_core` plus `decision_id` (or the full emitted receipt) instead of the ID-free core | `test_learning_contract::test_decision_receipt_id_excludes_itself_from_hash_core` |
| A replay receipt's own `receipt_id` can be folded into the hash it derives from, making the ID self-referential and unverifiable by a third party | `replay_receipt` domain-separated hash computation | `test_replay_receipt_is_byte_identical_for_identical_inputs` checks stability, not that the ID is excluded from its own input | Compute `replay_hash` over `replay_core` plus `receipt_id` (or the full emitted receipt) instead of the ID-free core | `test_learning_contract::test_replay_receipt_id_excludes_itself_from_hash_core` |
