§ 01

System Context — High Level

A single long-running supervised daemon (clawd) owns all connectivity, state, policy, routing, sessions, and tools. Telegram is the only surface in v1 (long-polling, no listen socket — better secure-by-default posture). The LLM is reached via one LLMProvider contract with two wire adapters (a Chat Completions adapter and a ChatGPT Responses adapter, selected by the CLAW_LLM_MODEL route). All state is local-first on the owner's machine.

§ 04

Concurrency — Per-Session Lane

Critical correctness trap. Swift actors do NOT serialize across await — an actor reentrantly admits other calls while a turn is suspended on a network await. “An actor serializes turns” is false. The lane uses explicit Task chaining.
SessionActor — Task chaining 
// One SessionActor per SessionKey. Holds one stored Task.
var currentTurn: Task<Void, Never>?

func enqueue(_ work: @Sendable @escaping () async -> Void) {
    let prev = currentTurn
    currentTurn = Task {
        _ = await prev?.value   // wait out the previous turn fully
        await work()            // run this turn to completion
    }
}

Default = strict FIFO per session. Plain messages queue. Only /stop (→ CANCELLED) and /new (→ SUPERSEDED + detaint) supersede. Cross-session work runs concurrently.

§ 05

Inbound Message Lifecycle — Normative Sequence

The most safety-critical invariant in the system. The offset cursor advances LAST — only after the inbound write commits. The dedup check (claimUpdate) is synchronous — never spanning an await.

Poison-update policy: if normalization of one update throws, advance the offset past it (never wedge the poller), log it, increment a dropped_updates counter surfaced in doctor.
§ 06

Run State Machine

RunState = PENDING / RUNNING / AWAITING_APPROVAL / DONE / FAILED / CANCELLED / SUPERSEDED. FSM invariants: synchronous reduce, no default arm, side effects after commit. A boot reconciliation sweep resolves orphaned states at startup.

Boot reconciliation sweep: any RUNNING at boot → FAILED (or re-enqueue via outbox); any expired AWAITING_APPROVAL → DENY. An updated_ts lease distinguishes stuck-forever from in-flight. The 60s ticker enforces PENDING → EXPIRED → DENY.
§ 07

Context Assembly — Instruction Hierarchy

Budget: inputCap = modelMax − reservedOutput, filled greedily by priority, grapheme-counted (String.count). Untrusted data is wrapped/labeled and can never claim system authority — durable memory is never injected at the system tier.

# Section Tier Priority Truncatable / Cap
1 System / security policy system trusted Highest No — degrade, never drop
2 Identity files (SOUL · AGENTS) system trusted High No
3 Developer config / tool policy (TOOLS) system trusted High No
4 Current date / time system trusted High No
5 Owner profile (USER.md) untrusted / labeled Med-high Yes — ≤ 1375 graphemes
6 Durable memory (MEMORY.md · memory_items) untrusted / labeled Med Yes — ≤ 2200 graphemes; overflow → error + consolidation
7 Session history / rolling summary mixed; provenance preserved Med Yes
8 Retrieved (FTS5 recall) + tool observations untrusted / labeled Low Yes — per-tool output cap ~25k tokens
9 Skills untrusted / labeled Low Yes
Security invariant: §5–6 (MEMORY.md / USER.md) is wrapped in the same untrusted/labeled wrapper as tool output. High-sensitivity memory is not auto-injected into a turn that already ingested untrusted content. Compaction preserves untrusted provenance — never folds a tool result into the trusted rolling summary.

§ 09

Development Roadmap — Technical Increments

Inc 0–3 = v1 daily-driver milestone: conversational + durable memory + read-only tools + streaming. Each increment lands a working supervised slice; “Done when” is an automated acceptance test, not a manual check.

Inc 0 · v1
Daily Driver
Supervised default-deny Telegram daemon (echo)
Bot echoes allowlisted DMs; un-allowlisted refused. Startup flock blocks second clawd. 409 handled as distinct typed error. Onboarding self-ID echo. Non-text “I can’t read X yet”. Doctor skeleton. Survives SIGTERM + restart.
Inc 1 · v1
LLM turn (blocking) + persistence
Real OpenAI-compatible answer; persisted (sessions / messages / runs / usage / audit + outbox + claimUpdate ordering). Escaper + splitter. Degradation UX. USD budget breaker. Context caps.
Inc 2 · v1
Streaming + per-session lane
SSE → throttled editMessageText. Per-session Task-chaining lane. Second message queues in order. /stop cancels. /new resets + detaints. SecretStore (no plaintext on disk).
Inc 3 · v1
Memory & workspace + read-only tools
Workspace files at untrusted tier (budgeted, caps, flush-before-compact). Durable facts on confirm. FTS5 recall. /memory. web_search / web_fetch / file READ at safe tier with exfil gate.
Inc 4
Scheduler & proactive
“Every weekday 07:00 Europe/Berlin” fires once per occurrence across restarts and DST changes. Confirm-before-arm. Reduced-privilege runs. Clock-gap catch-up. Opt-in heartbeat with quiet hours.
Inc 5
Write / shell tools + approvals + sandbox
Consequential tools require explicit approval (callback auth + ≥128-bit nonce + FSM). Forged or third-party callback cannot approve. Untrusted code in per-exec disposable VM. Enforced lethal-trifecta gate forces approval path in code.
Inc 6
Linux portability & deployment
Same source → running supervised binary on fresh Linux box (static SDK, distroless, systemd). CI Linux build including GRDB + FTS5 passes — the one hard portability gate.
